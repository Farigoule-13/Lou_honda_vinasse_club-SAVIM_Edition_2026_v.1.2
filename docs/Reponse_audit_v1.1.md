# Réponse à l'audit indépendant du 21/11/2026 — SAVIM Edition v1.0 → v1.1

Audit reçu : *Rapport d'audit indépendant — Lou Honda Vinasse Club · SAVIM Edition v1.0* (archive SHA-256 `265889ca…97bb`).
Chaque constat est corrigé dans le code **et** rejoué par un test automatique de `server/tests/audit.test.js`
(lancement : `cd server && node run-tests.js audit`). Suite complète : **52/52**.

| Constat | Correction | Test(s) de non-régression |
|---|---|---|
| **SV-01** Usurpation d'identité (C1) | Chaque téléphone tire une **clé secrète** (≈180 bits) qui ne quitte que vers l'hôte. Identifiant public = `m` + SHA-256(clé) tronqué à 128 bits. Le serveur recalcule l'empreinte à **chaque** envoi ou import : clé absente ou fausse → **403**, rien n'est modifié (ni note ni prénom). La clé n'est ni stockée par le serveur ni renvoyée. SHA-256 en JS pur (`vendor/sha256.js`, le `crypto.subtle` des navigateurs n'existant pas en `http://`), vérifié contre Node. Les téléphones v1.0 reçoivent leur clé automatiquement (migration, avec renommage de leurs vins et bouteilles) | I-01 rejoué (note 16 et prénom intacts) ; identifiant inventé / sans clé ; HTTP 403 et absence de fuite de la clé ; égalité JS / Node ; import d'un fichier falsifié refusé |
| **SV-02** Code par défaut public (C1) | Plus de `1664`. Au premier lancement : code **à 6 chiffres tiré au hasard** (`crypto.randomInt`), enregistré, affiché dans la console du serveur et sur l'écran de l'hôte **uniquement pour l'appareil local** (adresse de bouclage). Changer le code **ferme toutes les sessions**. Anti-devinette conservé (pause après 5 erreurs) | I-02 rejoué (1664 refusé) ; persistance du code ; unicité ; code invisible depuis une adresse du réseau ; sessions fermées après changement |
| **SV-03** JSON corrompu écrasé (C1) | Distinction absent / illisible. Fichier illisible : **jamais écrasé**, copié en `salon.json.corrompu-<date>`, reprise de `salon.json.bak` (copie de l'état précédent, tenue à jour à chaque écriture, au plus une fois par minute), **alerte** sur l'écran de l'hôte, la page Résultats et la console. En plus : copies horodatées toutes les 10 min (40 gardées), avant remise à zéro et avant restauration ; sauvegarde complète téléchargeable et restauration (code exigé) | I-06 rejoué (original préservé même après un nouvel envoi) ; cas sans copie lisible ; alerte visible ; cycle sauvegarde → remise à zéro → restauration |
| **SV-04** `note: null` → 0 (C2) | Conversion stricte : seuls un nombre fini ou un texte numérique sont acceptés ; `null`, `''`, booléen, tableau, texte → vote **refusé** (compté dans `rejected`). Champs facultatifs (degré, prix) : absents, jamais 0 | I-03 rejoué avec 7 valeurs invalides ; degré/prix nuls |
| **SV-05** Cœurs non limités au serveur (C2) | Quota de **3** imposé à chaque fusion : les 3 plus anciens sont gardés, les suivants retirés et signalés (`coeursRefuses`). Le calcul des classements applique la même règle (fichiers importés sans serveur) | I-04 rejoué ; limite sur plusieurs envois ; limite dans les classements |
| **SV-06** Horodatage futur bloquant (C2) | Toute date future est **ramenée à l'heure de réception** du serveur. Les dates aberrantes déjà stockées (v1.0) sont traitées comme « maintenant » lors d'une correction. Un renvoi identique n'est plus compté comme une modification | I-05 rejoué (correction ordinaire acceptée) ; donnée v1.0 aberrante corrigeable |
| **SV-07** Installateur sans `pipefail` (OBS) | `set -euo pipefail`. La nouvelle version est dézippée **à part**, ses tests tournent **avant** l'activation : échec → code de sortie 1, lien `~/lhvc-savim` et données de la version active **inchangés**. Les données sont copiées, jamais déplacées ; une version réinstallée est conservée en `.ancien-<date>` | Contrôle statique du script ; simulation complète (faux `pkg`, archive piégée dont les tests échouent) : sortie 1, ancienne version toujours active |
| **SV-08** Métadonnées partagées (OBS) | Un vin ajouté (`c-<idCréateur>-…`) ou une bouteille commune (`k-<idCréateur>-…`) porte l'identifiant de son créateur dans son nom : le propriétaire est **déduit de l'identifiant vérifié**, jamais du champ `by` reçu. Seul le créateur peut le modifier ; un autre téléphone peut seulement le faire connaître s'il manque (relais, remplacé ensuite par la version du créateur). `via` (influenceur) : seulement un identifiant de membre valide et différent de soi | Réécriture par un tiers refusée ; relais puis version du créateur ; commune protégée ; `via` invalide ignoré |

Toujours couverts : données et remise à zéro réservées à l'hôte, renvoi idempotent, aucune note d'autrui renvoyée aux téléphones,
comptage de la base (désormais **173 exposants / 465 cuvées**, après intégration de la vérification indépendante du 21/11).

## Ce qui reste hors de portée de ces tests
- Essais réels sur Android/Termux et Windows : à faire sur les appareils (`savim-test` sur le téléphone de l'hôte, `LANCER_TEST_PC.bat` sur le PC).
- Le fichier de notes 📎 contient la clé du dégustateur (c'est ce qui permet à l'hôte de l'importer) : il ne doit être envoyé qu'à l'hôte.
- La clé protège contre un autre appareil, pas contre quelqu'un qui aurait le téléphone (déverrouillé) d'un participant entre les mains.
- Pas de chiffrement sur le Wi-Fi local (http) : quelqu'un qui écoute le réseau du partage pourrait voir passer une clé. Le partage de connexion est protégé par mot de passe (WPA2), ce qui limite ce risque au cercle des participants.
